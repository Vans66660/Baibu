# 摆布 · 公开试用版 0.1

访客上传图片后，可框选或用中文或英文名称识别物品，拖动位置、围绕中心旋转、独立调整宽高、模拟盒状物品的侧面厚度、手动修补原位置并导出 PNG。首页、编辑器和 API 均由同一个 FastAPI 服务提供。当前没有账号、收费、图库或多用户任务队列。

## 这台 Mac 的局域网试用

目前可通过 `http://192.168.3.122:8001/` 让同一局域网的设备访问。`127.0.0.1` 只能用于访问者自己的电脑，不能作为分享地址。这台 Mac 已配置用户服务 `com.baibu.editor`，登录后自动启动并监听局域网；Mac 需要保持开机与唤醒状态。局域网 IP 可能随网络调整而变化。

## 本地预览

需要 Python 3.11。首次处理图片会下载 MobileSAM、LaMa 和按需使用的 Grounding DINO 权重；原版 SAM 可通过配置启用。

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
MODEL_DEVICE=cpu uvicorn app:app --host 127.0.0.1 --port 8001
```

打开 `http://127.0.0.1:8001/`。如果已安装 Docker，也可运行 `docker compose -f compose.preview.yaml up --build`，同样访问 8001 端口。直接双击 HTML 文件无法调用识别 API。
这台 8GB M1 Mac 默认使用 CPU：SAM 单独使用 MPS 可加速，但完整服务实测出现较高内存压力，整体比 CPU 慢。

## 将来部署到公网

准备一台可运行 Docker 的 Linux 服务器和指向服务器的域名。建议至少 16 GB 内存；CPU 处理长图可能需要数分钟。对外试用需要更快的处理速度时，使用 NVIDIA GPU 服务器并配置对应的容器运行环境。

1. 将整个目录复制到服务器。
2. 复制 `.env.example` 为 `.env`，将 `DOMAIN` 改成自己的域名；按需要调整 `HOURLY_LIMIT`。
3. 让域名 A/AAAA 记录指向服务器，并开放 80、443 端口。
4. 运行 `docker compose up -d --build`。Caddy 将为域名申请 HTTPS 证书，应用本身只暴露在内部容器网络。
5. 浏览器打开 `https://你的域名/`，先用示例图走完选物、移动、修补和导出流程。

这台 Mac 尚未安装 Docker，也没有现成域名和服务器；因此仓库里的容器配置已准备，但尚未在真实服务器验证。上线前应在目标服务器验证模型下载、内存和推理时长。

## 公开试用的边界

- 默认每个来源 IP 每小时最多 12 次处理请求，包括首次抠图和再次修补。这个限制保存在单进程内存中，重启会清零；多人正式运营应换成共享限额存储与任务队列。
- 服务一次处理一张图片；繁忙时返回 429。上传文件上限 12 MB、图片上限 400 万像素。
- 服务不创建用户图片库。上传数据在内存中处理；图片特征和结果会短暂缓存，闲置 5 分钟后失效，并按容量淘汰，不写入磁盘。浏览器负责保存导出的文件。反向代理日志不应记录请求体。
- 单张照片无法还原被遮挡的真实背景。复杂纹理、文字、人物和长阴影可能仍需手动修补。宽高与厚度编辑属于二维视觉调整。
- 公开发布前需确定域名、运营主体、对外隐私说明和支持渠道；当前产品名称为“摆布”。

## 技术组成

- Grounding DINO Tiny：按中文或英文名称定位目标。
- MobileSAM ViT Tiny：默认根据框生成物品蒙版；保留原版 SAM ViT Base 作为可选后端。
- LaMa：补全遮挡区域；平滑背景的手动修补可改用邻近像素填补。
- Canvas：在浏览器中拖动、调整宽高与导出。
- FastAPI + Caddy：推理 API、页面服务与 HTTPS 入口。

`GET /health` 返回服务状态。`POST /api/process` 接收 multipart `file` 和 `point`、`box` 或 `prompt`；`POST /api/repair` 接收背景图片和涂抹蒙版。设置 `PUBLIC_MODE=true` 会开启限额并关闭交互式 API 文档。

## 首页功能演示

首页演示进入视野后再按空闲时机加载素材；以预制背景和透明椅子图层演示选中、移动、独立调整宽高，约 14 秒循环一次。访客无需等待模型处理；支持暂停与继续，并会在离屏时暂停。系统开启“减少动态效果”时默认显示静止画面。演示背景经过单独修整，素材来源与提示词记录在 `ASSETS.md`。

### 中文物品名称

支持中文和英文名称。中文由本地 Helsinki-NLP/opus-mt-zh-en 模型转为英文，再交给 Grounding DINO 定位；首次中文识别会下载额外翻译权重。翻译模型在 CPU 推理，不调用外部翻译 API。建议输入简短的物品名称和颜色，识别不准时使用框选。模型来源：https://huggingface.co/Helsinki-NLP/opus-mt-zh-en （CC-BY-4.0，Helsinki-NLP）。

### 处理计时与缓存

`/api/process` 返回 `timings_ms` 和 `cache`。前端在画布下显示服务端总耗时，可展开查看模型准备、翻译、定位、SAM 预处理/特征提取/分割/蒙版整理、背景修补与图层合成、PNG 编码等步骤。日志只记录阶段耗时及缓存命中，不记录图片、名称或图片指纹。总时间不含浏览器上传、下载和显示时间；修补 API 的计时从工作线程开始。

同一张解码后图片＋相同选区/名称复用完整结果；重新框选同一图片复用 SAM 图像特征。内存缓存采用 LRU 与闲置 300 秒失效：图像特征最多 4 张、16 MiB 张量数据；结果最多 8 个、32 MiB 编码负载，另有少量 Python 元数据开销。过期条目在下次缓存访问时清理，进程重启全部清空。输入不同或失败的处理不复用结果；缓存命中仍遵守请求限额。缓存仅对当前单进程有效。名称翻译另使用最多 128 项的进程内缓存。

运行缓存回归检查：`python -m unittest discover -s tests -v`。

### SAM 独立设备配置（GPU 试验）

`SAM_DEVICE` 可单独指定 SAM 的 `cpu`、`mps`、`cuda` 或 `auto`；未设置时继承 `MODEL_DEVICE` 的解析结果。比如 `SEGMENTER_BACKEND=sam MODEL_DEVICE=cpu SAM_DEVICE=mps uvicorn app:app --host 127.0.0.1 --port 8001` 仅将 SAM 放到 Mac GPU，名称定位仍使用 CPU。翻译和背景修补保持原配置。`/health` 返回实际加载后的 `sam_device` 与 `detector_device`。

MPS 分割后释放 GPU 临时分配缓存，再按需加载背景修补模型，以降低两阶段的内存重叠。设备计时会等待 GPU 完成，避免只测到任务提交时间。GPU 不保证更快；这台 8GB M1 的完整服务试验没有获得收益，因此继续默认 CPU。切回 CPU 使用 `MODEL_DEVICE=cpu SAM_DEVICE=cpu` 并重启服务。

### MobileSAM（默认启用）

默认分割后端为 `mobile_sam`，保留 `SEGMENTER_BACKEND=sam` 以回到原版 SAM。这台 M1 使用 `MODEL_DEVICE=cpu SAM_DEVICE=cpu SEGMENTER_BACKEND=mobile_sam`。MobileSAM 同样支持图片特征缓存、中文名称定位、背景修补和导出，原有处理坐标不变。`/health` 显示当前加载的 `segmenter_backend`。

依赖来自官方固定版本源码归档；首次运行自动下载约 39 MiB 的官方权重到 PyTorch 缓存目录，下载时校验 SHA-256。无外部识别 API 调用。来源、固定版本和校验值见 THIRD_PARTY.md。

本机 768×512 室内图实测：完整服务首次处理约 6.4 秒（原 SAM CPU 约 15.7 秒）；服务已加载时处理镜像新图中的花瓶约 1.2 秒。1024×1536 录音卡片海报约 11.2 秒，其中背景修补约 9.2 秒。结果随选区、图片、硬件和负载变化。花瓶、椅子、落地灯和录音卡片的抠图与原模型轮廓接近，但不是逐像素一致；这些少量样例不能代表全部图片的准确率。

补充：中文名称首次识别仍需加载翻译与定位模型，本次中文首请求约 37 秒，不能把框选提速视为所有请求均为 1 秒。

### 框选确认

拖动选框并松开后保留范围，不会自动请求识别。检查选区后点击“确认识别”才提交；可以直接在图上重画、点击“重新框选”或按 Esc 取消。过小选区不会提交。中文名称输入仍使用输入框旁的“识别”按钮。

## 阴影清理与背景恢复

物品透明图层与背景修补范围分开计算。候选分割同时参考模型分数、选框覆盖及越界程度；对于周围颜色一致的平滑表面，额外寻找靠近物品、与修补边缘连通且色度相近的暗区。搜索距离及新增面积有限制，纹理复杂或判断不可靠时保留基础修补范围。这里使用颜色和几何规则，没有新增独立的语义阴影模型。

纯色或平滑渐变背景在周围样本符合颜色平面时直接插值恢复；复杂纹理仍由 LaMa 推测。原图在修补孔内部不参与混合，避免把旧阴影重新混回。阴影清理不会扩大产品透明图层。长投影、地毯、复杂遮挡仍可能留下残影或生成模糊，不能保证恢复被遮挡的真实纹理；可使用现有涂抹修补继续调整。

验证：`python -m unittest discover -s tests -v`。包含可控渐变背景投影、不相连暗色物体、相邻彩色物体、纹理回退和候选蒙版选择，以及缓存测试。

## 精细背景修复：本地参考纹理（可用）

识别物品后，展开“精细背景修复”：

1. 点击“开始修复”。物品暂时隐藏，但位置、宽高和旋转保留。
2. 涂抹补错的背景，只覆盖应属于同一种材质的区域，保留地毯、地板、墙面之间的边界。
3. 点击“框选参考纹理”。此时显示原图，从干净、同方向的地毯或桌面选取参考。至少 16 × 16 像素，建议更大；不要包含物品、阴影、异种材质或已涂抹区域。框选后不会自动请求修复。
4. 点击“生成修复预览”，可勾选“查看修复前”比较。满意才“确认采用”；放弃预览或退出修复不会替换背景。
5. 采用后继续移动、缩放、旋转并导出。修复期间禁用导出，避免把红色蒙版或参考框写入 PNG。

本地算法使用参考纹理的图块匹配和最小代价接缝，抑制参考区域的大范围照明条纹，在边缘作有限的梯度融合。涂抹范围外像素逐像素保持不变。相同输入可复用已有缓存。这是二维纹理合成，不是语义生成、三维重建或自动边界恢复；文字说明在本地模式不控制图像内容，UI 已明确标注。大面积、方向纹理或选错参考可能出现接缝，需要重新选参考或分区域处理。

验证：13 项 Python 测试通过；实际浏览器验证选框确认、画笔、参考框选、预览、前后对比、放弃、采用和 PNG 导出。测试图和性能仅代表当前样例，不代表所有照片的质量。

## 删除物品

识别完成后，在“尺寸与旋转”区域点击“删除物品”，即可隐藏前景物品并显示识别阶段已经补全的背景；这个操作不重复调用模型，响应是即时的。点击“恢复物品”可以随时还原前景图层，导出 PNG 会保留当前画面状态。

## GPU 生成修复：部署源码已准备，尚未运行模型

`gpu-worker/` 提供独立、Bearer Token 认证的 SDXL 局部重绘服务；`compose.gpu.yaml` 提供 NVIDIA GPU 部署配置。详见 [GPU 部署说明](gpu-worker/README.md)。当前 Mac 未配置 GPU 服务，因此页面 GPU 选项禁用，`/api/structure-repair` 明确返回 503，不会悄悄用本地算法冒充生成结果。

服务器配置 `BACKGROUND_WORKER_URL` 与 `BACKGROUND_WORKER_TOKEN` 后，页面可选择 GPU 模式。参考纹理先预填充修补区，再向 GPU 发送图像、蒙版和翻译后的背景说明。主服务再次强制只合成涂抹范围内的像素。GPU 超时或失败不会改变当前背景。GPU HTTP 接口使用模拟响应验证了错误处理和范围保护，但尚未在 CUDA 硬件上验证推理、模型效果、内存或速度。尚未加入 ControlNet 或自动语义背景分区。

## 当前产品路线

前期采用本地开源方案：MobileSAM / Grounding DINO / LaMa 与本地参考纹理合成，图像推理在运营方的 Mac 或自有服务器上完成。未启用付费云端图片编辑接口，网站没有 OpenAI 调用入口或 API 路由。移动、缩放和旋转在访问者浏览器完成。未来可单独验证自部署 GPU 开源模型；当前不能保证自动恢复所有隐藏背景结构。
